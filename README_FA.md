# سینا | مدیریت جلسات — آمادگی و تأیید و دعوت | نسخه ۱.۱۰

**نوع تحویل:** به‌روزرسانی افزایشی روی همان شاخه `main` و همان Vercel، بدون پروژه یا شاخه جدید.

## فایل‌ها (با رعایت مسیرهای دقیق)

- `api/index.js` — دو تغییر کوچک: import سرویس جدید و route `/api/v1/meeting-preparation` در تابع واحد موجود.
- `src/application/meetingPreparationV110.js` — فایل جدید منطق آماده‌سازی، بررسی، تأیید و اطلاع‌رسانی.
- `public/meeting-agendas-v13.js` — بدون تغییر منطق دستورجلسات نسخه ۱.۹؛ فقط بارگذار ماژول جدید به انتهای فایل افزوده شده است.
- `public/meeting-preparation-v110.js` — رابط کاربری جدید (فایل جدید).
- `public/meeting-preparation-v110.css` — سبک اختصاصی و فشرده (فایل جدید).
- `tests/meeting-preparation-v110.test.js` — آزمون‌های واحد اختیاری.

**نکته:** محتویات ZIP را مستقیماً روی همان پوشه‌های متناظر GitHub قرار دهید، نه همگی در ریشه. فایل‌های دیگر از جمله `vercel.json`، تقویم، بانک اسناد و منطق آپلود ۱.۹ تغییر نکرده‌اند. تعداد فایل‌های اجرایی داخل `api/` همچنان ۱۲ باقی می‌ماند.

## موارد عملیاتی

۱. کارت «آمادگی جلسه»: ورود به فهرست جلسات موجود و نمایش آمار تأیید و انتظار بررسی.
۲. نمایش عنوان، تاریخ، ساعت، برگزارکننده، شرکت‌کنندگان، دستورها، شرح دستور، قوانین و اسناد متصل و لینک دانلود پیوست‌های اختصاصی با دسترسی احرازشده.
۳. امکان تکمیل و ذخیره ایمیل و تلفن اعضا برای دعوت‌نامه، بدون تغییر اطلاعات اصلی اشخاص در تقویم.
۴. ارسال برای تأیید، تأیید رسمی مدیر احرازشده یا برگشت برای اصلاح با ذکر دلیل؛ تاریخ، عامل اقدام و سوابق در پایگاه داده ثبت می‌شود.
۵. تأیید به اثرانگشت نسخه محتوای جلسه و دستورها متصل است. بعد از تغییر جلسه، سند یا پیوست، تأیید قبلی به وضعیت «نیازمند بازنگری» تغییر می‌کند و ارسال مسدود می‌شود.
۶. ساخت و پیش‌نمایش دعوت‌نامه، چاپ، ارسال موردی به اعضا با کانال‌های قابل پیکربندی و گزارش وضعیت هر تلاش.

## سرویس‌های ارتباطی

- **ایمیل:** اتصال واقعی از طریق API سرویس Resend، مشروط به تنظیم در Environment Variables پروژه Vercel:
  - `RESEND_API_KEY`
  - `MEETING_EMAIL_FROM` (ایمیل دامنه فرستنده معتبر و تأییدشده)
- **پیامک:** اتصال از طریق API کاوه‌نگار، مشروط به:
  - `KAVENEGAR_API_KEY`
  - `KAVENEGAR_SENDER` (اختیاری)
- **اعلان داخلی:** در این نسخه پیام به عنوان «در صف» در سامانه ثبت می‌شود، اما تحویل واقعی به حساب عضو مستلزم توسعه حساب‌های کاربری اعضای سازمان است. وضعیت آن هرگز «تحویل شد» اعلام نمی‌شود.
- **واتساپ:** با کلیک کاربر، صفحه واتساپ برای مخاطب و متن جلسه باز می‌شود؛ ارسال با تأیید کاربر انجام می‌شود. ارسال خودکار پیاده نشده است.

توجه: هیچ سرویس بیرونی با نصب این نسخه خودکار فعال نمی‌شود. این سیستم هیچ کلید ارتباطی را در جاوااسکریپت مرورگر قرار نمی‌دهد. در پاسخ API واژه `accepted_by_provider` یعنی «پذیرش توسط سرویس» و نه تحویل قطعی.

## محدودیت‌های فعلی

- سامانه فعلاً از نشست کاربری مدیریت (`system_admin`) برای تأیید استفاده می‌کند، چون مدل احراز هویت مستقل برای تمامی مدیران و شرکت‌کنندگان سازمان هنوز پیاده‌سازی نشده است. تأیید با نام و نقش ادعایی کاربر انجام نمی‌شود؛ هویت از کوکی امن سمت سرور خوانده می‌شود.
- ایمیل و پیامک فقط با پیکربندی سرویس‌های مشخص‌شده ارسال واقعی دارند. تنظیم‌کننده نباید رمزها را در GitHub ثبت کند.
- لینک‌های فایل محرمانه به صورت عمومی در دعوت‌نامه بیرونی ارسال نمی‌شوند؛ دریافت پیوست تنها از API احرازشده سینا انجام می‌شود.
- این نسخه پیوست‌های فعلی دستورجلسات را نمایش می‌دهد، اما خطای آپلود قبلی را تغییر یا ادعای حل آن را ندارد.

## آزمایش پیشنهادی

۱. در «جلسات» وارد «آمادگی جلسه» شوید و یکی از جلسات دارای دستور را باز کنید.
۲. شرح دستور، سند مرتبط و دانلود پیوست (در صورت وجود) را بررسی کنید.
۳. ایمیل یا شماره همراه یک عضو را ذخیره کنید.
۴. «ارسال برای بررسی» و سپس «تأیید نهایی» را اجرا کنید. سوابق بررسی را ببینید.
۵. پیش‌نمایش دعوت‌نامه را بررسی کنید؛ بدون پیکربندی ایمیل یا پیامک، باید پیام «سرویس فعال نیست» نمایش داده شود.
۶. اگر دستور یا زمان جلسه پس از تأیید تغییر کند، باید وضعیت «تأیید نیازمند بازنگری» و ارسال مسدود شود.
